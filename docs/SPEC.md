# Bookshelf — Product & Technical Spec

Living spec. Every change to behaviour, data model or API updates this file in the same commit.

## 1. Purpose

A personal, self-hosted app for logging reading sessions (time + progress) across physical books, Kindle ebooks and audiobooks, with a book library populated by ISBN/search lookup, statistics, a calendar, goals and backups. Primary client is an iPhone (installed to the Home Screen as a PWA); the Mac browser works too.

Single user. No accounts. Not related to any employer.

## 2. Architecture

```
iPhone Safari (PWA) ──HTTPS──> tailscale serve (Mac) ──HTTP──> 127.0.0.1:4380  Node server (Hono)
                                                                 ├─ serves built web app (web/dist)
                                                                 ├─ /api/* JSON API
                                                                 ├─ SQLite (node:sqlite) — source of truth
                                                                 ├─ cover image cache
                                                                 └─ outbound: Open Library, Google Books, Notion API
```

- **Server**: Node ≥ 25, TypeScript executed directly by Node's type stripping (no build step for the server, no tsx). Hono + `@hono/node-server`. Binds to `127.0.0.1` only; remote access is exclusively via `tailscale serve`, so the tailnet is the security boundary and there is no app-level auth.
- **Database**: `node:sqlite` (`DatabaseSync`), WAL mode, foreign keys on. Schema managed by ordered, forward-only SQL migrations in `server/migrations/NNNN_name.sql`, tracked in a `schema_migrations` table. A migration never drops user data. A migration that rebuilds a table other tables reference (SQLite cannot alter a `CHECK` or `NOT NULL` in place) starts with the line `-- migrate:foreign-keys-off`: the runner then applies it with foreign-key enforcement off (create new table → copy → drop old → rename → recreate indexes), refuses to commit if `PRAGMA foreign_key_check` reports any violation, and always switches enforcement back on.
- **Web**: Vite + React + TypeScript, `vite-plugin-pwa` (service worker, manifest, icons), Recharts for charts, hand-written calendar grid, hand-written hash router (no router dependency).
- **Shared**: `shared/` holds Zod schemas and TypeScript types used by both server and web; the API contract lives there.
- **Offline**: the service worker caches the app shell. Mutations made while the server is unreachable are written to a Dexie (IndexedDB) outbox and replayed to `POST /api/sync` when reachable. Book lookup/search requires connectivity. Details in §6.1 and ADR 0007.
- **Data directory**: `BOOKSHELF_DATA_DIR`, default `~/Library/Application Support/Bookshelf/` containing `bookshelf.db`, `covers/`, `backups/`.
- **Config**: environment variables loaded from `.env` in the repo root (gitignored; `.env.example` committed). Never log secrets.

| Variable                | Default                                   | Purpose                                                 |
| ----------------------- | ----------------------------------------- | ------------------------------------------------------- |
| `PORT`                  | `4380`                                    | Server port (loopback only)                             |
| `BOOKSHELF_DATA_DIR`    | `~/Library/Application Support/Bookshelf` | DB, covers, backups                                     |
| `BOOKSHELF_TZ`          | system tz                                 | Timezone used to bucket sessions into days              |
| `GOOGLE_BOOKS_API_KEY`  | unset                                     | Optional; enables Google Books (keyless quota is zero)  |
| `NOTION_TOKEN`          | unset                                     | Notion internal integration secret                      |
| `NOTION_PARENT_PAGE_ID` | unset                                     | Page under which Bookshelf creates its Notion databases |
| `LOG_LEVEL`             | `info`                                    | `debug`, `info`, `warn` or `error`                      |

Config is validated at startup; an invalid value stops the server with a clear message. `NOTION_TOKEN` and `NOTION_PARENT_PAGE_ID` must be set together (or both left unset); the parent may be given as a page ID or a Notion page URL. The bind address is always `127.0.0.1` and is not configurable.

## 3. Conventions

- IDs: UUID v4 strings generated by whoever creates the record (client or server) — required for offline creation and idempotent sync.
- Timestamps: ISO 8601 UTC strings in storage and API, normalised to millisecond precision (`2026-11-14T09:30:00.000Z`) so they compare correctly as strings. Day bucketing uses `BOOKSHELF_TZ`: a session belongs to the local day on which it **started**.
- Naming: the database uses snake_case columns; JSON on the wire uses camelCase (`coverUrl`, `pageCount`, `startedAt`).
- UI: British English; dates displayed `DD/MM/YYYY`; durations `1h 05m` (under an hour: `45m`); audio positions `h:mm:ss`.
- Soft delete: syncable entities carry `deleted_at`; reads exclude them; backups include them.
- Every syncable row has `updated_at`; sync conflicts resolve last-write-wins on `updated_at`.

## 4. Domain model

| Entity            | Key fields                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Book**          | id, title, subtitle, authors[], publisher, published_date, language, synopsis, cover_url (remote), cover_path (cached file name in `covers/`, server-managed), isbn10, isbn13, genres[] (from source subjects, user-editable), source (`openlibrary`\|`googlebooks`\|`manual`), source_id, status (`to_read`\|`reading`\|`finished`\|`dnf`), rating (0.5–5 step 0.5, nullable), created_at, updated_at, deleted_at |
| **BookFormat**    | id, book_id, format (`physical`\|`kindle`\|`audiobook`), page_count (physical/kindle, nullable), audio_duration_seconds (audiobook, nullable), isbn (nullable), timestamps. A book may have several formats; progress across formats is unified via percentage.                                                                                                                                                    |
| **Read**          | id, book_id, number (1 = first read, 2+ = rereads), started_at, finished_at, outcome (`in_progress`\|`finished`\|`dnf`), timestamps. Sessions belong to a read.                                                                                                                                                                                                                                                    |
| **Session**       | id, read_id, book_id, format_id, started_at, ended_at, duration_seconds (stored; may differ from ended−started if paused), progress_unit (`pages`\|`percent`\|`audio_seconds`), start_value, end_value, start_percent, end_percent (derived server-side from unit + format length), note, timestamps                                                                                                               |
| **ActiveTimer**   | at most one row: id, book_id, format_id, started_at, resumed_at (start of the current running segment), paused_at (null while running), accumulated_seconds (earlier segments), created_at, updated_at. Elapsed = accumulated + (running ? now − resumed_at : 0). Survives app closure; stopping it opens the "log session" form prefilled, and the client discards it once the session is saved.                  |
| **Tag** / BookTag | id, name (unique, case-insensitive), colour; many-to-many with Book                                                                                                                                                                                                                                                                                                                                                |
| **BookNote**      | id, book_id, kind (`note`\|`quote`), text, location (free text e.g. "p. 42", "34%", "1:02:10"), timestamps                                                                                                                                                                                                                                                                                                         |
| **Goal**          | id, kind (`books_per_year`\|`pages_per_year`\|`minutes_per_day`), year (nullable for daily), target, timestamps                                                                                                                                                                                                                                                                                                    |

Derivations:

- **Percent**: pages → `value / format.page_count * 100`; audio → `value / format.audio_duration_seconds * 100`; percent → as is. Clamp 0–100. If the length is unknown the percent is null and the UI asks for it.
- **Current read** of a book = its live read with the highest number (any outcome). **Current progress** = end_percent of the latest session (by start time) in the current read that has a known percent.
- **Read bookkeeping** (REST only; sync replicates rows as sent): setting a book to `reading` opens a read if none is in progress; `finished`/`dnf` close the in-progress read (or record a closed read when the book has none); `to_read` leaves reads alone. Logging a session without a `readId` uses the in-progress read, opening one if needed, and moves a `to_read` book to `reading`; a session that starts before its read moves the read's `started_at` back. `POST /api/books/:id/reads` refuses (409) while a read is in progress.
- **Pages read** in a session = end − start for page sessions; otherwise the percent delta × the format's page count (never negative; 0 for audiobooks).
- **Reading speed** per format = progress delta ÷ duration over the last 30 days (pages/hour, %/hour, listening speed ratio for audio).
- **Estimated finish** = remaining % ÷ recent %/day, where recent %/day = progress made by the current read's sessions started in the last 14 local days (including today) ÷ 14. Days are rounded up. Null when progress is unknown, the read is not in progress, or there is no recent progress.
- **Streak**: consecutive local days with ≥1 session (today counts if it has a session; otherwise the streak ending yesterday is still "current").

## 5. API (all JSON under `/api`, Zod-validated both ways, errors as `{ error: { code, message } }`)

Conventions:

- Request bodies, queries and **responses** are validated against the schemas in `shared/schemas.ts`; a response that fails validation becomes a 500 rather than reaching the client.
- Status codes: `201` for creates (including `PUT /api/goals/:id` when it creates), `200` otherwise, `204` (no body) for deletes. Errors: `400 validation_error` (bad body/query/path, or a body that references a record that does not exist), `404 not_found` (path resource missing or soft-deleted), `409 conflict` (duplicate id, duplicate tag name or goal period, invalid timer transition, read already in progress, database constraint), `502 upstream_error` (lookup/Notion failure), `400 unsupported_backup`, `400 notion_not_configured`, `409 notion_busy`, `500 internal_error`. Validation errors include `details: [{ path, message }]`.
- Create bodies may carry a client-generated `id`; reusing an existing id (even of a deleted row) is a 409.
- Book responses are `BookListItem` (`GET /api/books`) or `BookDetail` (single book): the book plus `tagIds`, live `formats`, `currentRead`, `progressPercent` and `coverSrc` (`/api/covers/:id` or null); detail adds `reads` and `estimatedFinish` (`{ percentPerDay, daysRemaining, date }`).
- `from`/`to` query parameters are inclusive local dates (`YYYY-MM-DD`). Omitted bounds mean all time for `stats/summary`; `stats/daily` defaults to the 30 days ending today (or ending `to`) and accepts at most 3660 days.
- Lookup: `isbn` → 404 when neither source knows it, 502 when a source failed and nothing was found. Search falls back to Google Books when Open Library returns nothing or fails, 20 results per page. Candidates' `publishedDate` is normalised to `YYYY`, `YYYY-MM` or `YYYY-MM-DD` when recognisable (otherwise kept as given); `language` is the source's code (`en` or `eng`). Search candidates take ISBN, language, publisher, date and cover from Open Library's best edition, never another edition's ISBN; without an edition, language is set only when the work lists exactly one. Edition/work descriptions are tidied (CRLF, markdown source links, "Contains" appendices, trailing `--back cover`). Keyless Google Books requests are currently refused (zero anonymous quota), so without `GOOGLE_BOOKS_API_KEY` Open Library is the only synopsis source.
- Bodies are limited to 2 MB (100 MB for `POST /api/backup/import`).

### 5.1 Sync semantics (`POST /api/sync`)

- Entities: `book`, `format`, `read`, `session`, `tag`, `note`, `goal`, `timer`; at most 500 ops per request, applied in order, each in its own transaction.
- `upsert` payloads are the full client record without timestamps (`syncPayloadSchemas` in `shared/`). The stored row gets `updated_at = clientUpdatedAt`, keeps its `created_at` (or takes `clientUpdatedAt` when new) and is un-deleted. Session percents are re-derived; a book's `coverPath` is server-managed; a book's optional `tagIds` replace its tag links (unknown tags are ignored). `delete` payloads are `{ id }` and soft-delete (cascading for books; the timer is removed).
- Last-write-wins: an op is `stale` (ignored) when the stored row's `updated_at` is later than `clientUpdatedAt`; ties apply.
- Results: `{ opId, status: 'applied' | 'stale' | 'error', duplicate, error? }`. Applied and stale ops are recorded in `sync_ops`; replaying an `opId` returns the original status with `duplicate: true`. Errors (`validation_error`, `not_found` for a missing referenced row, `conflict`, `internal_error`) are not recorded, so the client can retry after fixing the cause (e.g. sending a missing parent first).
- Sync replicates rows; it does not repeat REST side effects (read bookkeeping in §4). Clients send every row they changed.

## 6. Screens (mobile-first, safe-area aware, light/dark)

Layout: a bottom tab bar (Today, Library, Calendar, Stats, Settings) with Add book reached from Today and Library; hand-written hash routes (`#/`, `#/library`, `#/add`, `#/books/:id`, `#/log?book=:id&timer=1`, `#/calendar?month=YYYY-MM`, `#/stats`, `#/settings`). iPhone standalone mode: `env(safe-area-inset-*)` padding, 44pt touch targets, 16px inputs (no zoom on focus), no horizontal scroll at 320px+, system fonts, light/dark palettes as CSS custom properties with WCAG AA contrast. Dates show `DD/MM/YYYY` in the **device's** timezone (the server buckets days in `BOOKSHELF_TZ`; keep them the same). Every chart has a text summary and a data table; chart colours are validated for colour-vision deficiency and no chart uses two y-axes.

1. **Today** — active timer (start/pause/stop), currently reading with progress bars and estimated finish, today's minutes vs daily goal, streak.
2. **Library** — shelves (Reading, To read, Finished, Did not finish), filter by tag, search; add book.
3. **Add book** — scan barcode (camera via `zxing-wasm`), type ISBN, or search title/author; pick a candidate; confirm formats & lengths; or enter manually.
4. **Book detail** — cover, synopsis, metadata, formats, progress chart over time, sessions list, notes & quotes, tags, rating, status, reread.
5. **Log session** — book, format, start/end or duration, progress in the format's natural unit (pages / % / h:mm:ss) with toggle to %, note.
6. **Calendar** — month grid; each day shows covers of books with sessions; tap a day for its sessions.
7. **Stats** — range picker (week/month/year/all), daily minutes bar chart, pages/percent trend, breakdown by format/genre/tag/author, reading speed, goals progress, year in review.
8. **Settings** — goals, tags, backup (export JSON via share sheet/download, import JSON, Notion sync + status), server status, offline outbox status.

Behaviour decided in phase 2:

- **Today**: elapsed time is always derived from the timer's timestamps (`accumulatedSeconds` + now − `resumedAt`), never from a counting interval, so it survives the app being closed. "Stop & log" opens Log session prefilled from a fresh `GET /api/timer` (`startedAt`, `serverTime` as the end, `elapsedSeconds` as the duration; offline, from the cached timer at the current time); the timer is discarded (`DELETE /api/timer`, 404 ignored) after the session is saved. Estimated finish comes from each reading book's detail. Today's minutes come from `stats/daily` for today.
- **Library**: the full list is loaded once (cached for offline use) and filtered on the device: shelves by status, a tag filter, and search (title, subtitle, authors, ISBNs; case- and accent-insensitive). Searching spans all shelves.
- **Add book**: Scan (rear camera, EAN-13 978/979 only, decoded by zxing-wasm whose `.wasm` is served from our origin), ISBN (ISBN-10/13 validated with `normaliseIsbn`), Search (20 per page, "More results"; choosing a result that has an ISBN-13 but no synopsis fetches `GET /api/lookup/isbn/:isbn13` and merges it over the result with `mergeCandidates`, falling back to the result alone on any error — ADR 0008), or Manual. 404 and upstream errors offer manual entry prefilled with the ISBN. The confirm step edits the metadata, chooses formats with page counts / audiobook length (`h:mm:ss`), the shelf, and warns when the ISBN is already in the library. Candidate covers in search results load from the lookup source's URL (the only third-party request, made only while searching); saved books always use `coverSrc`. Lookups and creating books need the server.
- **Book detail**: status and rating (`<select>`, ½-star steps) and notes/quotes work offline; tags, formats (edit length, add, remove), reread (`POST /reads`, shown when no read is in progress), session deletion and book deletion need the server. The progress chart plots the current read's sessions with a known percent (shown from two sessions). Metadata shows the publication date with `formatPublishedDate` (`DD/MM/YYYY`, `MM/YYYY`, `YYYY`, or as entered) and the language by name (`languageName`, e.g. `eng` → English); search results show dates the same way.
- **Log session**: book (when not given), format, timing as "Start & end" (duration follows end − start until edited, so breaks can be subtracted) or "Duration" (end = start + duration), progress in the natural unit (pages, or `h:mm:ss` for audiobooks) with a toggle to %, converting the values; start value prefilled from current progress. Always sends an explicit `startValue` and a client-generated `id`.
- **Calendar**: Monday-first month grid; days with sessions show up to three tiny covers (+N) and are buttons; tapping one lists that day's sessions (`GET /api/sessions?from=day&to=day`).
- **Stats**: Week = last 7 days, Month = last 30 days, Year = 1 January to today, All time = no summary bounds and the last 3660 days of daily data. Year and All time group the daily series by month. Separate single-series bar charts for minutes, pages and percent; breakdowns show the top 8 by time. Year in review offers the last 10 years.
- **Settings**: goals for this year's books/pages and minutes per day (`PUT /api/goals/:id`, reporting created vs updated), tag create/rename/recolour/delete, backup export (share sheet when files can be shared, else a download named `bookshelf-backup-YYYY-MM-DD.json`), import (validated on the device against the backup schema, confirmed, then `POST /api/backup/import`), Notion sync (button disabled with a progress message while running) and status, server status (`/api/health`), and the outbox: pending/failed counts, last attempt, "Sync now", and per-change Retry (failed) / Discard.

### 6.1 Offline behaviour (ADR 0004, ADR 0007)

- **Server unreachable** means `fetch` failed, or a proxy answered 502–504 without the API's error envelope (e.g. `tailscale serve` while the Mac server is down). A 502 with an envelope (`upstream_error`) is a normal error.
- **Read model**: the last good response of every resource is kept in IndexedDB and shown immediately while refreshing; offline, screens render from it. Values are re-validated with their schema when read; entries older than 90 days are pruned at start-up. API responses are never cached by the service worker; covers have a same-origin runtime cache.
- **Offline writes**: session logging, timer start/pause/resume/discard, book status and rating, and note/quote create/edit/delete. Each is queued as full records in dependency order (book → read → session). Because sync never opens reads, the client mirrors the §4 bookkeeping: it creates the read row itself (next number, starting at the session start), moves a read's start back for a retrospective session, re-shelves `to_read` books as `reading`, and opens/closes reads on status changes. The projected result is written to the read model.
- **Replay**: before any online write, on start-up, on the `online` event, when the app becomes visible, when the server becomes reachable again, every 30 seconds while ops are pending, and from Settings → Sync now. Batches of up to 500 ops, in order, single-flight. `applied`/`stale` ops are removed; `not_found` is retried indefinitely (a parent may still be on its way); any other error is retried until it has failed 3 times in a row, then the op is marked failed, no longer sent, and surfaced (banner + Settings) for Retry or Discard.
- An offline banner shows when the server is unreachable, with the pending count; failed changes link to Settings. Book lookup/search and other online-only actions say they need a connection.

## 7. Backups

- **Automatic local snapshots**: on server start and daily at 03:00 local, write the JSON export to `backups/bookshelf-YYYY-MM-DD.json` (local date; a later snapshot the same day overwrites it), keeping the latest 14. A startup after 03:00 counts as that day's snapshot. The check runs every minute so it survives sleep and DST.
- **JSON export/import**: as §5. `schemaVersion` is the highest applied migration; backups newer than the server are refused. Backups contain every user table including soft-deleted rows and the timer, but not server state (`settings`, `sync_ops`, `notion_pages`). Import is all-or-nothing and always snapshots first to `backups/bookshelf-pre-import-<timestamp>.json` (these are not pruned). Covers are not in the JSON; they are re-downloaded on demand.
- **Notion**: the server calls the Notion API (`Notion-Version` pinned in code) with `NOTION_TOKEN`. On first run it creates three databases under `NOTION_PARENT_PAGE_ID` — _Bookshelf Books_, _Bookshelf Sessions_, _Bookshelf Notes_ — and stores their IDs in a `settings` table. Each run upserts rows keyed by a `Bookshelf ID` text property (stored Notion page IDs avoid duplicates). Notion is a one-way mirror; restore is from JSON. Respect Notion rate limits (~3 req/s, retry on 429 with `Retry-After`).
  - Pinned `Notion-Version: 2022-06-28`. The stored page ID is used when known; otherwise the database is queried by `Bookshelf ID` before creating, so a lost mapping never duplicates pages. Rows whose mirrored properties are unchanged (content hash in `notion_pages`) are skipped; soft-deleted rows have their pages archived.
  - Missing or archived databases are recreated at the start of a run (recreating _Books_ recreates the other two, whose `Book` relation must target it); a changed parent page starts fresh databases. Old databases are left for the user to remove.
  - Runs are synchronous (the request returns the counts), one at a time (`409 notion_busy`); 5xx and network errors are retried with backoff. Status (last run, last success, last error, last result) is kept in `settings`.

## 8. Imports

- **Bookpine CSV export**: the format is known from the user's sample export; the importer is being built (tracked in README "Roadmap").
- **Notion database import is out of scope**: the user confirmed it would hold the same data as the Bookpine export. Notion remains a one-way backup mirror (§7, ADR 0006); nothing is ever read back from it.

## 9. Operations

- `npm run dev` — server (watch) + Vite dev server with `/api` proxy.
- `npm run build` — type-check + build web into `web/dist`.
- `npm start` — production server serving `web/dist`.
- PWA: `vite-plugin-pwa` generates `manifest.webmanifest` (name "Bookshelf", `display: standalone`, `start_url: /`, theme colours, 192/512/maskable-512 icons) and a Workbox service worker (`sw.js`, auto-update) that precaches the built assets including the zxing `.wasm`, falls back to `index.html` for navigations except `/api/*`, and runtime-caches `/api/covers/*`. `index.html` carries the iOS tags (`apple-mobile-web-app-capable`, status-bar style, title, `apple-touch-icon`). Icons are generated by `npm run icons` (`scripts/generate-icons.ts`, Node built-ins only) and committed in `web/public/`.
- HTTP caching of the built app: `index.html` (and every SPA-fallback HTML response), `sw.js`, `registerSW.js` and `manifest.webmanifest` are served with `Cache-Control: no-cache` so a new build is picked up; content-hashed `/assets/*` get `public, max-age=31536000, immutable`. A missing `/assets/*` file is a 404 (never the SPA shell), so a stale client cannot cache HTML under a script URL. Other root files (icons) use default caching.
- launchd agent: `npm run service:install` (`scripts/service.ts`, Node built-ins plus the server's config module) renders the template `ops/com.bookshelf.server.plist` into `~/Library/LaunchAgents/com.bookshelf.server.plist` and loads it with `launchctl bootstrap gui/<uid>`. The agent runs `<node> <repo>/server/index.ts` with `WorkingDirectory` = repo, where `<node>` is the absolute path of the Node that ran the install (its stable PATH symlink, e.g. `/opt/homebrew/bin/node`, when that is the same binary); `RunAtLoad` (start at login); `KeepAlive` = `{ SuccessfulExit: false }` (restart after a crash or error exit, not after a clean shutdown) with `ThrottleInterval` 30 s; stdout/stderr to `BOOKSHELF_DATA_DIR/logs/bookshelf.log` / `bookshelf.err.log`. Its environment is `NODE_ENV=production`, a `PATH`, and `BOOKSHELF_TZ` = the Mac's timezone at install time (`Intl`), omitted when `.env` sets `BOOKSHELF_TZ`; everything else comes from `.env`, which the server reads itself. Install validates the configuration, builds the web app if `web/dist/index.html` is missing, replaces an already-loaded agent (`bootout` first), refuses if the port is held by anything else (naming the program via `lsof`, or a manually started Bookshelf via `/api/health`), and waits up to 15 s for `/api/health`. `service:uninstall` = `bootout` + remove the file (data and logs kept; works with an invalid `.env`); `service:status` = file, `launchctl print` state/pid/last exit code, health (exit 1 unless answering) and a warning if the agent's Node binary no longer exists; `service:logs [-n N] [-f]` tails the logs. `node scripts/service.ts plist [--out FILE]` renders the agent without installing it.
- Tailscale: `npm run tailscale:serve` (`scripts/tailscale.ts`) runs `tailscale serve --bg <PORT>`, which exposes `https://<mac-name>.<tailnet>.ts.net/` (Tailscale certificate, persistent across restarts) to the user's tailnet only, proxying to `http://127.0.0.1:<PORT>`. The CLI is `tailscale` on PATH or `/Applications/Tailscale.app/Contents/MacOS/Tailscale`; when neither exists the script prints install instructions. Before serving it reads `tailscale status --json` and stops with instructions unless `BackendState` is `Running` and `CertDomains` is non-empty (HTTPS certificates enabled; MagicDNS mentioned when off); it warns if the server is not answering yet, skips serving if `tailscale serve status --json` already has a handler proxying to the port, and prints the HTTPS URL found there afterwards. `tailscale:status` prints state, MagicDNS/HTTPS, the Bookshelf URL and server health (exit 1 unless served). `tailscale:off` runs `tailscale serve --https=<listener port> off` for the listener serving Bookshelf only (other serve config is left alone). Documented in README.

## 10. Quality gates

`npm run check` = ESLint + Prettier check + `tsc --noEmit` (server, shared, web) + Vitest (server API integration tests against a temp SQLite DB with external HTTP mocked; shared derivation unit tests; web component tests with Testing Library + jsdom; outbox tests with fake-indexeddb). Target ~90% line coverage on `shared/`, `server/`, `scripts/` and `web/src/` (each enforced as a Vitest threshold). No external network in tests: `fetch` is injected and mocked; the only real sockets are loopback ones (the boot test of `server/index.ts` and the ops scripts' port probe). Ops scripts are tested with `launchctl`/`tailscale` and other commands injected and faked; they never load an agent or change Tailscale settings. Tests never touch the real data directory.
